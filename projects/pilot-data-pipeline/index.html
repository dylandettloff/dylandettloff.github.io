A local ingestion pipeline for fictional water-treatment measurements. It validates rows, preserves rejected records for inspection, prevents duplicate imports, and produces a clean dataset and threshold report.

What happens when a file arrives?

01 / INGESTHash CSV bytes
02 / VALIDATECheck every row
03 / STORECommit to SQLite
04 / REPORTExport clean data

Unchanged file contents are skipped, even if the filename changes. Invalid values and repeated asset/timestamp pairs enter quarantine. Valid rows and their batch record commit together.

Designed for repeat runs

  • SHA-256 content fingerprints prevent importing the same file twice.
  • UTC timestamps and physical-range checks normalize the input.
  • Transactions keep batch and measurement records consistent.
  • Conflicting measurements retain the existing value and enter quarantine.

A fresh implementation

This demo uses original Python code, a new schema, SQLite, and synthetic flow, conductivity, and pressure readings. It demonstrates general ingestion and monitoring concepts. It contains no employer logs, source code, cloud identifiers, or credentials.

It runs locally. Cloud upload, scheduling, and email delivery are not implemented in this demo.

Run it in two commands

python pipeline.py --output output
python pipeline.py --output output

The second run reports skipped. No packages or cloud account are required. The output folder contains a SQLite database, clean CSV, and JSON report.

Validation evidence

Automated checks cover invalid timestamps, non-finite values, duplicate records, renamed files, modified files with overlapping measurements, and invalid headers. Operational thresholds are illustrative and separate from physical validation ranges.
